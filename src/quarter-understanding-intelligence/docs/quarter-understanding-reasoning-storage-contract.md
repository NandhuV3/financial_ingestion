# Quarter Understanding Reasoning Storage Contract

## 1. Purpose

Quarter Understanding introduces the first LLM-powered reasoning layer.

The platform must preserve:

* Raw reasoning
* Final assembled artifacts

as separate assets.

This contract defines ownership, storage, versioning, regeneration, and auditability requirements for raw reasoning outputs.

---

## 2. Why Raw Reasoning Is Stored

The platform must preserve what the model actually produced.

Without raw reasoning storage:

```text
Prompt debugging becomes impossible.

Model comparison becomes difficult.

Regression analysis becomes difficult.

Reasoning audits become difficult.
```

The final Quarter Understanding artifact is not sufficient.

The assembled artifact contains deterministic infrastructure added by the builder.

The platform must also preserve the original reasoning output.

---

## 3. Two Artifact Model

Quarter Understanding consists of two independent artifacts.

### Reasoning Artifact

Generated by:

```text
LLM
```

Contains:

```text
Reasoning only
```

Examples:

```text
summary
semantic_anchor_key
category
importance
signal_agreement
company_knowledge_alignment
supporting_signal_ids
```

---

### Understanding Artifact

Generated by:

```text
Builder
```

Contains:

```text
Final assembled understanding
```

Examples:

```text
metadata
lineage
confidence
evidence references
business keys
hashes
versions
```

---

## 4. Ownership Boundary

### LLM Owns

```text
reasoning-raw.json
```

Conceptually.

### Builder Owns

```text
current.json
archive/*
```

for assembled Quarter Understanding artifacts.

The Builder must never modify raw reasoning.

The LLM must never generate assembled artifacts.

---

## 5. Future Storage Layout

Future storage may use:

```text
warehouse/
  companies/
    {ticker}/
      quarter-understanding/
        {period}/
          current.json

          reasoning-raw.json

          archive/
```

This document reserves the convention.

It does not implement storage.

---

## 6. Reasoning Artifact Requirements

The reasoning artifact must remain:

* Immutable
* Auditable
* Reproducible
* Independently readable

The artifact must preserve:

```text
Original model output
```

without modification.

---

## 7. Reasoning Schema Version

Raw reasoning must contain:

```text
reasoning_schema_version
```

Example:

```text
1.0.0
```

Purpose:

* Track prompt contract evolution
* Track response contract evolution
* Determine compatibility with builders

Reasoning schema versions are independent from artifact schema versions.

---

## 8. Model Metadata

Reasoning storage should preserve:

```text
model_version
prompt_version
generated_at
```

Purpose:

* Model comparison
* Prompt comparison
* Regression testing
* Audit review

The platform must be able to answer:

```text
Which model produced this reasoning?
```

and

```text
Which prompt produced this reasoning?
```

---

## 9. Regeneration Independence

Reasoning and understanding artifacts must support independent regeneration.

Examples:

### Builder Logic Changes

If:

```text
confidence scoring changes
```

Then:

```text
Rebuild understanding artifact only.
```

No LLM call required.

---

### Prompt Changes

If:

```text
prompt changes
```

Then:

```text
Regenerate reasoning artifact.
Regenerate understanding artifact.
```

---

### Repository Changes

If:

```text
storage implementation changes
```

Then:

```text
No LLM regeneration required.
```

---

## 10. Input Hash Requirements

Reasoning artifacts should preserve:

```text
input_hash
```

Purpose:

```text
Detect stale reasoning.
```

The reasoning input hash represents:

```text
Company Knowledge
Business Signals
Filing Metadata
```

used during generation.

---

## 11. Auditability Requirements

The platform must be able to reconstruct:

```text
Inputs
↓
Raw Reasoning
↓
Builder Assembly
↓
Final Understanding
```

for any historical period.

Auditability is a first-class requirement.

---

## 12. Historical Preservation

Raw reasoning artifacts are historical records.

Future archive policies should preserve:

```text
reasoning-raw.json
```

alongside:

```text
current.json
archive/*
```

Reasoning history should never be overwritten.

---

## 13. Failure Recovery

If:

```text
Builder fails
```

after reasoning generation:

The reasoning artifact should remain recoverable.

The platform should support:

```text
Reasoning
→ Rebuild Understanding
```

without re-calling the LLM.

This reduces cost and improves recovery.

---

## 14. Non Goals

This phase does not define:

* Repository implementation
* File IO
* Storage services
* Database storage
* Cloud storage
* Retention policies
* Compression

This document defines storage ownership only.

---

## 15. Success Criteria

A successful reasoning storage architecture:

* Preserves raw model output
* Separates reasoning from infrastructure
* Supports independent regeneration
* Supports prompt evolution
* Supports model evolution
* Supports audits
* Supports regression testing

Raw reasoning is a first-class platform artifact.

It is not a temporary intermediate object.
